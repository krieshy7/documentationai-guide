## Start your first Agent Flywheel integration

Choose the integration that matches your runtime and required access boundary.

| Integration | Best fit | Capability boundary |
| --- | --- | --- |
| **Python SDK** | A Python agent exposed through `module:attr` | Serves the agent with `text`, `messages`, or `dict` input |
| **OpenClaw** | A full workflow integration | Requires conversation access enabled as a separate host permission |
| **DeepSeek Harness** | Observe-only tracking | Tracks `tools/result` outcomes without controlling rollouts or production turns |

Setup flow: choose an integration, install its SDK or plugin, configure the required permission or credential, then start the integration using the instructions in its tab.

<Tabs>
<Tab title="Python SDK" icon="code">

Use the Python SDK when your agent entry point is available as a `module:attr` reference. The SDK accepts `text`, `messages`, and `dict` input shapes.

<Steps>
<Step title="Install the SDK" icon="download">

```bash
pip install agent-flywheel
```

</Step>

<Step title="Configure credentials" icon="lock">

Set `PERCEPTEYE_API_KEY` in the environment that starts your agent. Use a key with the `pefw` prefix.

</Step>

<Step title="Serve your agent" icon="rocket">

Pass your agent's `module:attr` entry point, identifier, and input shape.

```python
import agent_flywheel as fw

fw.serve("my_package.agent:build", agent_id="my-coding-agent", input_shape="text")
```

Set `input_shape` to `text`, `messages`, or `dict` to match the input your agent accepts.

</Step>
</Steps>

</Tab>

<Tab title="OpenClaw" icon="package">

Use the OpenClaw plugin for the full workflow integration. Node `>=22.22.3` is required, and conversation access is a separate host permission from plugin installation.

<Steps>
<Step title="Install the plugin" icon="download">

```bash
openclaw plugins install @percepteye/agent-flywheel
```

</Step>

<Step title="Enable conversation access" icon="users">

Enable conversation access in OpenClaw before using the full workflow. This host permission is separate from installing the plugin.

</Step>
</Steps>

<Callout kind="info">

Plugin installation does not grant conversation access. Enable the host permission explicitly before using the full workflow.

</Callout>

</Tab>

<Tab title="DeepSeek Harness" icon="bar-chart">

Use the DeepSeek Harness plugin to track `tools/result` outcomes. Node `>=22.22.3` is required.

<Steps>
<Step title="Install the plugin" icon="download">

```bash
dsh plugin --profile <name> add @percepteye/agent-flywheel
```

Replace `<name>` with the DeepSeek Harness profile name.

</Step>
</Steps>

<Callout kind="alert">

DeepSeek Harness is observe-only. It does not claim rollouts, capture production turns, or apply prompt or model changes.

</Callout>

</Tab>
</Tabs>
