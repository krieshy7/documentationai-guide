What changed in each release. `agent-flywheel` (Python) and `@percepteye/agent-flywheel` (Node) ship the same version number in the same release. The current version is **0.3.0**.

```bash
pip install -U agent-flywheel                   # upgrade the Python SDK
npm view @percepteye/agent-flywheel version     # latest published Node plugin
```

<Update label="2026-10-20" description="v0.3.0" tags={["feature", "security"]}>

### New features

- **`agent-flywheel login --agent-id <name>` gets an agent its key from the terminal.** It prints a short code, opens launch.percepteye.ai with the code filled in, and once you sign in and click **Approve**, stores the `pefw_` key in `$PERCEPTEYE_HOME/credentials.json` (mode 0600, written atomically). The Node plugin reads the same file. `agent-flywheel logout` forgets it.
- **A stored key is used automatically.** The order is `api_key=`, then `PERCEPTEYE_API_KEY`, then the key stored for that agent on that control plane. `serve()`, `attach()`, `current_policy()`, `current_prompt()` and `policy_source()` say once when they use a stored key.
- **`serve()` offers to create a key in a terminal.** With no key and a person at the terminal, it asks `Create one now (free)? [Y/n]`, runs the same login, and carries on. It never asks in CI, with `PERCEPTEYE_NO_PROMPT=1`, or without a terminal; there it raises as before.
- **Neither SDK sends a `pefw_` key in a request body.** Any key found in a body, for example in a tool's output, is replaced with `pefw_[REDACTED]` before it leaves.

### Changes

- **Every refusal caused by a missing key says where a key comes from.** `serve()`'s error, the `current_policy()`, `current_prompt()` and `policy_source()` warnings, `attach()`'s `upload_refusal`, and `agent-flywheel install-hooks` / `status` now name `agent-flywheel login` and end with the sign-up address, `https://launch.percepteye.ai/onboard/agent-sdk`.

</Update>

<Update label="2026-10-13" description="v0.2.0" tags={["feature", "improvement", "bugfix", "breaking", "security"]}>

### New features

- **The control-plane URL has a default.** `control_plane_url=`, then `PERCEPTEYE_CONTROL_PLANE_URL`, then `https://launch.percepteye.ai/api/flywheel/v1`, each trimmed, with a blank value falling through. `serve()` no longer refuses a missing URL; the key is the only thing that can be missing. `agent-flywheel install-hooks` and `status` name the URL they resolved to.
- **A second consent tier for what the model saw.** With an operator's model-content grant, the LangChain and Google ADK adapters observe each model call inside an `attach()` turn (system instructions, the whole input, the tool definitions offered, the answer) and every tool result, and the turn uploads it as one OpenTelemetry GenAI trace, `genai_trace`. Off by default and observe-only: without the grant nothing of it is recorded, not even to disk.
- **`rules=` on `serve()` and `attach()`** declares the Product's workflow rules once, after registration. `None` sends nothing and `[]` retracts. A refusal costs only the rules, and a slow rulebook route never holds back startup.
- **A withdrawn model is given back.** When the control plane answers `withdrawn: true`, `policy_source()` reverts to the snapshot it was constructed with (your own configuration) and reports it once as `changed`, with the new `PolicySnapshot.withdrawn` field set. `is_withdrawn()` is exported, and both `policy_source()` and `apply_current_policy()` log the withdrawal once. Before, a withdrawal was read as "keep what you run", and the agent stayed on the candidate a person had rolled back.

### Changes

- **Breaking: `on_change` now also fires on a withdrawal,** with an empty snapshot. A callback or turn loop that builds a client from the snapshot must check `snap.withdrawn` and go back to its own configuration.
- **Breaking: your flywheel key opens only the control plane's own gateway.** A `pefw_` key goes to an endpoint only when the control plane names `PERCEPTEYE_API_KEY` for it and it sits at your control plane's origin. It is no longer a fallback credential for provider endpoints. `endpoint_kwargs()` takes `flywheel_key=` and `control_plane_url=`, and its `api_key=` stays your own credential for the endpoint. An endpoint with no `model` is no longer applied. A production agent pointed at a self-hosted endpoint keeps its own configuration until the control plane serves the gateway URL.
- **The goose hook claims practice tasks only in training mode,** and only with a key set. An unreadable mode claims nothing. `install-hooks` and `status` say which applies.
- **`attach(retention_turns=...)` refuses a value that is not a whole number 0 or more,** before capture starts. The Node plugin gains the same setting as `retentionTurns`.
- **A bounded tool or error body keeps both ends** behind a marker that counts what it replaced, and an error body gets 4000 characters instead of 1000.
- **Artifacts travel only in the rollout report.** The SDK no longer posts each artifact to a separate route.
- **A per-process socket no longer changes the agent's execution identity,** so restarting an agent no longer invalidates a prepared run.
- **The Prime adapter seals its kernel:** a harness snapshot requires its kernel virtualenv, Python path variables are removed from every environment it configures, and a rollout whose kernel failed to start is excluded as `substrate_unavailable`.

### Fixes

- **A `policy_source()` refresh that cannot reach the control plane is now a failed refresh:** `last_refresh_ok` goes `False` and `stale_for_s` grows while the last good snapshot stands. An outage used to report a fresh, healthy policy.
- **A rollout's outcome is never lost:** every terminal path reports, and a model call that could consume a whole episode is bounded by a ceiling derived from the episode budget.

</Update>
